# 引擎推荐逻辑缺陷 + 设计原则 — 实盘复盘

> 初版：2026-07-28 · 扩充：2026-07-30

> 性质：**产品/策略逻辑缺陷 + 设计原则**,非崩溃类 bug;不阻塞,但系统性影响推荐质量与用户盈亏

关联:`docs/code-review-architecture-and-issues.md` §3 问题清单(本文件是其补充,聚焦「推荐质量与是否 fit 用户处境」)。

## 共性根因(一句话)

**引擎按「单标的 × 单策略 × 单时点」的静态数据打分,缺三种"状态感知":**
1. **用户全局状态**(组合净敞口、集中度)
2. **跨信号一致性**(regime / IVR / IV-RV / view 是否自相矛盾)
3. **时间尺度 / 事件状态**(财报前后、漂移 edge 在该天期是否存在)

下面 4 条缺陷都是这个根因的不同侧面;末尾 2 条设计原则是修复时应遵循的底层判断。

# Part A — 缺陷清单

## 缺陷 1 — 组合级 delta 感知缺失 🔴 P1

### 现象
引擎给出 **QQQ iron_condor**(9/18,POP 80.5%,EV +0.16)。因 put skew,该铁鹰**净多 ~+$5.4k delta/张**。而用户账户已 1.27× 超配多头 —— 推荐**继续往同一方向加码**,与「降风险」完全相反。

### 根因
策略选择只看单标的的 IV/RV/IVR/regime/POP/EV,**完全不读取用户当前持仓的净敞口**。`runEngineLive` / `oppScanner` 的输入里没有「组合 net delta / 单名集中度」这类上下文。

### 影响
- 用户想中性收 theta,却在不知不觉中被推成 1.27× 净多。
- 「诊断出超配 → 引擎却继续推多头」形成反向拉扯,用户需人工识别每张卡的组合贡献。

### 建议修复
1. 引擎/Dashboard 计算并展示**每张推荐卡的净 delta 贡献**($ 与占账户 %)。
2. 可选:传入组合 net-delta 上下文,对「加剧现有敞口」的卡做降权或打标(如 ⚠「会把你的净多头从 1.27× 推到 1.30×」)。
3. 最小版本:先在卡片上显示单卡 `net $delta`,把判断权交给用户,不做自动降权。

## 缺陷 2 — `long_straddle` 事件触发未校验波动率是否便宜 🔴 P1

### 现象
**WMT long_straddle**(9/18,财报 8/20,POP 38.1%,EV +0.06,净付 $10.14)。同一张卡上:

| 信号 | 值 | 指向 |
|---|---|---|
| IVR | **71(偏高)** | 卖方 |
| IV vs RV | 28.7% > 24.3%(+4.4pp)| 期权**偏贵**,卖方 |
| regime | **sell** | 卖方 |
| 推荐 | **buy** long_straddle | 买方 ⟵ 与上面全部矛盾 |

在「三个信号一致喊卖波动率」的环境里,推了个**买波动率**、且穿越财报吃 **IV crush** 的仓。

### 根因(代码定位)
- `directionalView.ts:83-90`:`neutral-vol`(唯一触发 `long_straddle` 的 view)判据本应是 **IVR 极低(<20)** 或 **临近财报 + IV 偏低**。此处走「临近财报」一路,但**「IV 偏低」那一半未被校验**,靠事件临近单独触发。
- `oppScanner.ts:275-303` `regimeBonus`:`long_straddle` 属 `BUY_STRATEGIES`,`regime=sell` 应得 0.6× 惩罚;高 IVR 也应偏卖方。**事件驱动路径绕过了这些护栏。**
- `calibration.ts:5-9, 58-63`:代码明确记载 long_straddle **系统性失血**(「52%-win…loses −3.48/trade」),校准专门用均值 $ 盈亏压制它。**事件路径能绕过 regime 惩罚 + 校准抑制。**

### 建议修复
1. **加一道 vol 便宜度闸**:事件驱动 `long_straddle` 需**同时**满足 `IV < RV`(或 `IVR < 阈值`,如 40),否则在 `regime=sell` + 高 IVR 时降级为卖方结构、或不推。
2. 若保留财报 straddle,卡片显式标注「买入高 IV,穿越财报有 IV crush 风险」,并让 EV 计入 crush(核对 `index.ts:367` `crushIv` 是否覆盖此路径)。
3. 复核事件路径为何绕过 `regimeBonus` 惩罚与 `calibration` 抑制。

## 缺陷 3 — 财报后 IV-crush 盲区 + 滞后动量 view = 事后诸葛亮 🔴 P1

### 现象
财报日(07-29)当天,两票刚报完(**MSFT beat +7% 盘后 / META miss −7% 盘后**),引擎次日推:

| 卡 | 推荐 | 关键数 | 问题 |
|---|---|---|---|
| MSFT | **看涨** bull put spread | IVR 90「极高」,IV 43.7% vs RV 34.7%,POP 96.9%,EV 3.65 | 财报**已利好跳涨后**才推看多 |
| META | **看跌** bear call spread | IVR 81,aiView bearish「**近5日跌6.6% + MACD 负**」,POP 95.7% | 财报**已利空暴跌后**才推看空 |

**冒烟的枪**:两张卡都提示「需关注**10月27日**财报」,但两票**当天(07-29)刚报完财报**——引擎把风险指向下一次财报,却在用**这一次**财报撑起的高 IV 推卖方。**引擎没有"催化剂刚点燃过"这个状态。**

### 根因(两个叠加机制)
1. **aiView 是滞后价格驱动**(`directionalView.ts`:chg5d / MACD)→ 大涨后转多、大跌后转空 = **外推已发生的 move**。财报跳空是**事件驱动**,不是趋势,顺势做正撞均值回归。706 单里 **268(38%)触及止损**即此表现。
2. **IV/IVR/POP/EV 用财报前的陈旧数据**:价格更到了盘后,但 IVR 90/81「极高」是**财报本身撑起的尖峰**,财报一出 **IV crush** 立刻发生 → 「IV溢价卖方收租」的 edge **正在蒸发**;POP/EV 用**事件前分布**算,已失真。**新鲜的壳,过期的 edge。**

### 建议修复
1. 加**"财报刚发生"窗口检测**(距上次 earnings < N 天):窗口内**抑制**基于高 IVR 的卖方推荐,或用**剔除财报尖峰的 IVR** 重算。
2. **aiView 区分"事件跳空"与"趋势性 chg5d"**,别把财报 gap 当动量。
3. 事件窗口内给 POP/EV 打**「数据可能失真」**标记,不照常呈现 96.9%。

## 缺陷 4 — 净多头偏向导致回测负收益 + 校准降权过弱 🔴 P0/P1

### 现象(Performance 回测页,706 单已回测)
累计 **−$5,153**、平均 **−$7.41/单**、胜率 56.5% 但**均值为负**。按方向重排,规律一目了然:

| 方向 | 结构 | 盈亏 | 胜率 |
|---|---|--:|--:|
| 🐻 空 | 熊市看跌价差 | **+$17,956** | 56.8% |
| 🐻 空 | 看跌信用价差(bear call)| **+$7,869** | 71.0% |
| 中性 | 铁鹰 | +$2,143 | 71.2% |
| 🐂 多 | **看涨信用价差(bull put)** | **−$15,063** | **46.9%** |
| 📈 多波动 | **跨式买入(straddle)** | **−$12,116** | 48.6% |
| 🐂 多 | **看涨债务价差(bull call)** | **−$7,775** | **32.6%** |

**空头结构全赚、多头结构全亏;straddle 实盘 −$12k = 每单 −$327,坐实缺陷 2/校准的警告。** bull put/call 胜率跌破 50%(本该 70%+)= **方向常年做错**,不是尾部偶发。最弱环境 **Buy(低 IVR)46.3%、−$5,658**。

### 根因
1. **结构性净多头偏向**(bull put/call + put-skew 铁鹰),与把用户账户做到 1.27× 的是同一偏向。
   > ⚠ **因果需收紧**:「空全赚/多全亏」可能**叠了两个因素**——① 样本期偏空的市况,② 结构净多的偏向。方向结论**只作 P0 线索**,不等于「引擎永久偏见」;落地前必须用 **regime×策略分层**或**对照期**验证,避免把「这段市况」全归因成引擎缺陷。
2. **aiView 滞后动量**(见缺陷 3)→ 涨时转多、反转被碾。
3. **已知输家没被真正关掉**:straddle + 低 IVR 买方。校准是**温和 clamp(0.4–1.4×)不是硬关**,`DISABLE_PNL=−2.5` 门槛太高;方向性 **debit 结构还直接不进校准**,更不会被压;3463 条里 2616 未满观察期,反馈闭环太慢。

### 建议修复
1. **治多头偏向**:给净多结构设上限,或要求更强方向确认才推(见设计原则 ①)。
2. **硬杀已证输家**:straddle 37 单 −$12k 早过 catastrophic,应**硬关**而非温柔降权;调灵敏 `DISABLE` 闸门。
3. **提速反馈**:对明显亏损组合降低样本门槛,别让 shrinkage 把它按在 1× 太久。
4. 接**组合视角**(缺陷 1):结构上偏多的引擎 + 看不见用户已很多 = 双重多头。

# Part B — 设计原则(修复时的底层判断)

## 原则 ① — 漂移 edge 随时间尺度衰减:看多放 LEAP,短天期保持中性

> 🟠 **这是产品哲学换挡,不是 bugfix。** 执行它 = **自动板放弃大量 bull put/call 短天期方向推荐**。落地前必须**单独拍板**:「自动板是否去方向化(短天期只做中性)」是产品决策,应先定规则、再改打分,不能当纯技术修复偷偷做掉。

**"市场长线向上"是真的,但它是 LEAP 尺度的 edge,传导不到 30 天的方向性结构上:**

- 年化上涨 ~8–10% → **30 天漂移 ≈ 0.8%**,而 30 天波动 ≈ **5.5%** → 漂移仅 **~0.15σ,被噪声淹没**。
- 漂移相对 edge **随天期增长**:2 年 LEAP 的漂移 ~20% vs 波动 ~30% → ~0.6–0.8σ,**这才有意义**。
- 结构上,bull put/call 价差是**封顶收益 + 大下行**:大涨不参与(封顶)、急跌全承受 —— **用错工具捕捉漂移**。

**原则**:
- **漂移用 LEAP / 长仓 / 不封顶结构捕捉**(用户的 LEAP 袖子 = 其"市场会涨"的正确载体,调到目标净敞口 0.5–0.7×)。
- **短天期期权保持 delta 中性**(收波动率溢价),**不承担方向** —— 30 天没有漂移 edge,带方向只是叠相关多头,急跌一起爆。
- 引擎若要表达短期方向性看多,用**更长天期 / 不封顶**结构,而非封顶价差。

## 原则 ② — 铁鹰按每侧 delta 目标构造(delta 对称、strike 不对称),校验净 delta ≤ 0

- **strike 对称 ≠ 中性**:因 put skew,等距离时短 put 的 |delta| > 短 call → 整条**净多**(这正是缺陷 1/4 的微观来源)。
- **要中性,让两条短腿 delta 相等**(如各 16Δ)→ 因 skew,等 delta 出来的 **strike 不对称:put 更远、call 更近**。

**原则**:
- 铁鹰**按「每侧目标 delta」构造**,而非按 strike 距离或等权利金。
- 建完**校验净 delta ≈ 0**;对**净多账户可设 ≤ 0**(略偏空以对冲长仓)。

## 评审收紧(2026-07-30 复审)

落地时以下约束**优先于**上面的粗略修法:

1. **缺陷 4 因果分层**:方向结论作 P0 线索,用 regime×策略分层 / 对照期验证,别定性成永久偏见(已内联到缺陷 4 根因)。
2. **"绕过"要钉死代码路径**:`regimeBonus` / `calibrationMultiplier` **仍乘在扫描分上**——更可能是**护栏太弱**(`neutral-vol` 强制选 straddle + 非卖方在 `sellVolTier` 恒 `qualified` + 分数仍 >0 就上板),**未必是"完全绕过"**。修法应落在**硬闸**(vol 便宜度闸 / 禁上自动板),而非只调 multiplier。**动手前先读代码确认真实上板路径。**
3. **原则 ① 是产品决策**:短天期去方向化会砍掉大量推荐,先拍板再改打分(已内联到原则 ①)。
4. **缺陷 1 分两步且解耦**:最小版「卡上显示净 $delta」**无条件先做**;自动降权要定义**无持仓 / RH 桥断线**时的降级,别把扫描器和券商强耦合。
5. **原则 ② 有代价**:等 delta 铁鹰 credit 更薄、POP/EV 变化。应写成**目标函数** `|netDelta| ≤ ε`(账户偏多时可 `≤ 0`),**接受权利金下降**,而不是只改构腿公式。
6. **财报后窗口别一刀切**:「N 天禁高 IVR 卖方」会误杀 crush 后仍贵的真 edge。默认方案 = 窗口内**降权 / 要求 IV−RV 仍显著 / 用 ex-earnings IVR** + 打「数据可能失真」标记,而非硬禁。

## 落地顺序(复审微调版)

| 阶段 | 做什么 | 缺陷/原则 |
|---|---|---|
| **P0 止血** | 自动板**硬关(或极严闸)`long_straddle`**;事件触发**必须 `IV<RV` 或 `IVR<阈值`**;下调 `DISABLE` / 对灾难桶更快硬关 | 缺陷 2、4 |
| **P1 可见性** | 推荐卡展示 **net delta($ 与占账户 %)**;铁鹰改**等 delta + 校验 `|netDelta|≤ε`** | 缺陷 1、原则 ② |
| **P1 产品决策** | **是否执行原则 ①**(短天期去方向化)——先定规则再改打分 | 原则 ① |
| **P1 事件状态** | 财报后窗口(降权/ex-earnings IVR/失真标记)+ view 区分 gap vs 趋势 | 缺陷 3 |

**共性**:先**止血**(硬闸已知输家)→ 再**感知**(卡片 delta 透明 + 中性构腿)→ 最后做难的**时间状态机**。原则 ① 先拍板再动大改。各阶段另开分支。
